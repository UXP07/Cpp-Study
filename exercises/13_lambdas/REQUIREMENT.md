// 练习 13 —— Lambda 与闭包：捕获的四种姿势（知识点 #5 Lambda 与闭包）

## 背景

你已经写过七道题的类——现在换个视角：**lambda 就是编译器替你写的小类**。
捕获列表 = 那个类的成员初始化列表，调用 = 成员函数 operator()。
你练了一个月的所有权、值语义、mutable 状态，全部直接搬进来。

四个术语先翻成白话：

- **闭包**：lambda 造出来的那个"带状态的函数对象"（编译器偷偷生成的匿名类的一个实例）
- **捕获**：把外面的变量带进闭包——`[x]` 复印一份（按值），`[&x]` 留个地址（按引用）
- **mutable**：允许改"复印进来的副本"（默认当 const 供着，改不了）
- **init 捕获**（`[x = 表达式]`）：给闭包成员起名、就地构造——能把 move-only 的东西塞进闭包

场景：行情系统的"回调工厂"——各种可调用物从工厂里造出来、传出去、带状态地活着。

**零输出要求**照旧；注释不要求；main 留空；判题端驱动验证。

## 需求

### Part A：四个工厂（全部返回闭包本体，auto 返回）

**Q1. `make_multiplier(int k)`**
返回"乘以 k"的可调用物。按值捕获——工厂返回后闭包依然安全
（想想：复印进来的 k 和工厂栈帧有什么关系？没有关系，这就是安全的原因）。

**Q2. `make_counter()`**
返回一个计数器：每调用一次返回 1、2、3……递增。用 init 捕获
`[n = 0]` + mutable 实现。**拷贝会分叉**：拷出来的闭包从拷贝时刻的值
各自继续数——这个行为是验收项（闭包是对象，各数各的）。

**Q3. `make_probe(int& cell)`**
返回"把 cell 加一"的可调用物——**引用捕获**：调用闭包改的是外面的
原变量（不是副本）。参数是调用方传进来的引用，闭包只是留了地址。

**Q4. `make_owner(std::unique_ptr<int> p)`**
返回"读出所持值"的可调用物。把 unique_ptr **塞进闭包**（init 捕获 +
std::move）。这个闭包**不可拷贝**（编译期负向特征验收）——
成员的拷贝性决定类的拷贝性，闭包不例外。

### Part B：捕获 this

**Q5. class Accumulator**
成员 `total_`（初值 0）；`total()` 查询；`adder()` 返回捕获 `[this]` 的
lambda：接收一个数、累加进 total_、返回累计值。同一个 Accumulator
的两个 adder 闭包共享同一个 total_（都攥着同一个 this）。

### Part C：lambda 定制 STL 算法

**Q6. 三个自由函数，内部必须用 lambda 做定制**：
- `sort_by_abs(const std::vector<int>&)` → 返回按**绝对值升序**排好的新数组
- `count_over(const std::vector<int>&, int threshold)` → 返回大于阈值的元素个数
- `squares(const std::vector<int>&)` → 返回每个元素平方的新数组

## 验收标准（判题端驱动逐条核对）

- `make_multiplier(3)(5)==15`、`(-2)==-6`；工厂作用域结束后依然正确
- counter：连续调用得 1、2、3；拷贝后 c2 数出 4、5，**原闭包 c() 仍得 4**（分叉证据）
- probe 调用两次后，外面的 `cell == 3`（引用捕获改原变量）
- `make_owner(42)(...) == 42`；owner 闭包**不可拷贝**（static_assert 负向）；
  multiplier 闭包可拷贝（正向）
- Accumulator：`add(5)==5`、`add(3)==8`、`total()==8`；第二个 adder 从 9 续涨
- `sort_by_abs({-5,2,-3,1}) == {1,2,-3,-5}`；`count_over({1,5,9,2},4)==2`；
  `squares({1,2,3}) == {1,4,9}`
- 全程零输出零警告
