// 练习 07 —— 连接与锁：五法则的两条出路（复习：对应练习 06 / 知识点 #1）

## 背景

交易网关里有两类典型资源：

- **网关连接 Conn** —— 复制一条连接意味着向服务器再要一条（贵，但语义成立）；
- **临界区守卫 ScopedLock** —— 复制一把"已持有的锁"，意味着两个对象都会去解锁
  同一把锁，或者各自阻塞等一把永远不来的锁（语义根本不成立）。

同一个五法则，两类资源走出两条路：Conn 全件实现并升级赋值写法（copy-and-swap 统一赋值），
ScopedLock 干脆禁掉拷贝、只留移动。本题把两条路都走通。

**本题零输出要求**：两个类不打印任何东西。一切验收由判题端驱动机器完成
（活连接计数 + 编译期特征 + try_lock 证据链）。你只交类本身，main 留空即可。

## 需求

### Part A：class Conn —— 可复制的资源类

**Q1. 资源与获取**
连接上下文 = 堆上 `new char[]` 存放 endpoint 字节串（裸数组，禁用 string/vector/
智能指针充当存储）。构造函数接收 endpoint（`const std::string&`），**先校验容量再分配**，
拷贝内容入堆；容量满抛 `std::runtime_error`。
静态接口：`live()` 返回当前存活连接数；`set_capacity(n)` 设置容量（默认不限）。
计数语义：**构造 +1、拷贝构造 +1、移动构造不变**（过户不是新开）、释放 -1。

**Q2. 拷贝构造**
深拷贝上下文（新分配、新计数），源毫发无损；容量满同样抛异常。
提供 `endpoint()` 查询，返回 std::string。

**Q3. 移动构造**
接管指针与长度，源置空（`endpoint()` 为空串、可安全析构）；`noexcept`；
**容量满时也必须成功**（SR4 要讲清为什么）。

**Q4. 统一赋值（copy-and-swap）**
赋值只写一个：`operator=` **按值收参**，配合成员 `swap(Conn&) noexcept` 完成一切。
要求：
- 自赋值天然正确，不需要 `this != &other` 特判
- 容量满时 `a = b` 抛异常，且 a 原内容完好（强异常保证）
- 右值赋值走移动路径：编译期特征 `is_nothrow_move_assignable<Conn>` 为 true，
  `is_nothrow_copy_assignable<Conn>` 为 false

### Part B：class ScopedLock —— 禁拷贝、只移动的守卫

**Q5.** 构造接收 `std::mutex&` 并加锁；析构时若仍持有则解锁。
拷贝构造与拷贝赋值 **`=delete`**（SR1 要讲清判据）。移动构造/移动赋值：
移交持有权，源变为不持有；均 `noexcept`。提供 `holds()` 查询当前是否持锁。
单线程即可验证（判题用 `try_lock` 做证据链）。

## 验收标准（判题端驱动逐条核对）

- `live()` 全程精确：构造/拷贝 +1、移动不变、析构 -1，全部作用域结束后归零（泄漏探测器）
- 深拷贝成立：拷贝后销毁源，副本 `endpoint()` 内容完好；两对象互不影响
- 容量异常：第 N+1 个构造抛 `runtime_error`，计数不漂移，程序继续
- 强保证：容量满时 `a = b` 抛异常，a 内容不变、计数不变
- 饱和状态下移动赋值依然成功（move 不受容量约束）
- 编译期特征：`ScopedLock` 不可拷贝；两类移动构造/移动赋值均 noexcept；
  Conn 统一赋值呈现"拷贝可抛、移动不抛"
- ScopedLock 运行期证据链：持有（try_lock 失败）→ 移交（源 `holds()` 为假、
  锁仍被持有）→ 移动赋值接管 → 析构释放（try_lock 成功）

## 简答题（答案写在 main.cpp 顶部注释块）

SR1. Conn 保留拷贝、ScopedLock 删除拷贝——各自的判据是什么？
     给出"一个资源类该不该禁拷贝"的通用判断准则。
SR2. 统一赋值 `operator=(Conn)` 按值收参，为什么能同时覆盖拷贝赋值和移动赋值？
     重载决议发生在哪一步？它为什么天然不需要自赋值特判，代价是什么？
SR3. copy-and-swap 的强异常保证来自哪里？
     把"可能抛异常的操作"和"修改自身的操作"的先后关系说清楚。
SR4. 为什么移动构造在容量满时也必须成功、且 live 计数不变？
     这与移动操作标 noexcept 有什么内在联系？

## 约束

- Conn 上下文必须裸 `new[]/delete[]`（参数与返回值可以用 std::string）
- ScopedLock 基于 `<mutex>` 的 std::mutex；不需要多线程，单线程即可
- Conn 赋值必须用统一形式（按值 + swap），不得拆成两个赋值运算符；
  ScopedLock 拷贝必须 `=delete`
- C++17（g++ 8.1）；注释中文；**两个类零输出**
- 构建：`cmake --build --preset default --target 07_conn_guard`
