## 需求

### Part A：手写部分

**Q1. class Msg —— 行情消息**
堆上 `(ptr, len)` 字节缓冲（**禁** string/vector/智能指针充当存储；内容按字节存取，
不保证终止符——想清楚读回时的正确姿势）。构造接收数据指针、长度、id；
查询：`size()`、`data()`（`const unsigned char*`）、`id()`；静态 `live()`。
不可拷贝。

**Q2. template Ref\<T\> —— 共享引用句柄（Shared 的变体 + 两个新成员）**
- 生命周期全套：默认构造（空）、`explicit` 接管裸指针、拷贝（计数 +1）、
  移动（`noexcept`，计数不变、源置空）、拷贝赋值/移动赋值、析构
  （**最后一份释放时资源与控制块同亡**）
- **`reset()`**：主动释放份额、回到空状态——空对象上调用必须安全，连续调用安全
- **`explicit operator bool()`**：语境布尔——`if (ref)` 可用，但不允许 `ref == 1`
  这类隐式转换编译通过
- `get()`、`use_count()`（空返回 0）、`operator*`、`operator->`
- **空状态矩阵全覆盖**：默认构造、拷贝空、移动空、对空移动赋值、空上 reset、
  空判 bool——全部安全且语义正确（这是本题主考）

**Q3. 计数纪律（上次的突袭复查项）**
`Msg::live()` 与 `use_count()` 全程精确对应：接管 +1 资源、拷贝只 +持有者、
移动谁都不加、reset / 赋值放旧 / 析构按最后一份判定资源死亡——
**每条路径上资源死亡恰好一次**。

### Part B：std 智能指针实操（三个持有姿势）

**Q4.** 三个类，构造函数分别接收（按值）`std::unique_ptr<Msg>`、
`std::shared_ptr<Msg>`、`std::weak_ptr<Msg>`——三个签名就是三种所有权语义的
表达（为什么是这三个，SR1 要答）。成员类型自选（行为会逼出正确选择）：

- `Owner`：独占。类整体不可拷贝、可移动；持有的消息随它生死
- `Subscriber`：共享。两个 Subscriber 持同一条消息，`use_count` 正确联动；
  提供访问内部句柄的接口
- `Observer`：观察。**不延长消息生命周期**；提供 `peek()`——活着返回可用的
  shared_ptr（可查 id），已死返回空

## 验收标准（判题端驱动逐条核对）

- Msg：(ptr,len) 内容逐字节正确、无终止符依赖、live 精确
- Ref 空状态矩阵：默认构造 / 拷贝空 / 移动空 / 对空移动赋值 / 空 reset ×2 /
  空 bool——全安全，`use_count()==0`、`get()==nullptr`、`operator bool` 为假
- Ref 计数链：接管 1 → 拷贝 2 → reset 归 0 且 live 同步降 → 再 reset 安全；
  移动后计数不变；拷贝赋值放旧加新一次到位
- `explicit operator bool`：`if (ref)` 编译且语义对；`ref == 1` **不得**编译
- Owner：不可拷贝（编译期特征）、移动后 live 不变；Subscriber：use_count 联动；
  Observer：消息释放后 `peek()` 得空、live 归零
