// 练习 18 —— 条件变量：谓词等待与优雅关停（知识点 #11；依赖 17 的锁）

## 背景

17 号解决了"安全地改"，没解决"高效地等"——消费者空转轮询浪费 CPU，
忙等不是等待。条件变量让线程**睡到条件成立**，但它的 API 有三个经典坑：
虚假唤醒、丢失唤醒、关停叫不醒。这三个坑的解药是同一个：**谓词等待**。

三个术语白话：

- **条件变量（condition_variable）**：让线程排队睡觉、条件可能满足时被叫醒
  的设施——必须配一把 mutex 使用
- **谓词等待**：`cv.wait(lock, 谓词)` = "睡到谓词为真"——醒来自动重查，
  等于语言帮你写好了 `while (!pred) cv.wait(lock);` 循环
- **优雅关停**：关闭标志 + notify_all——消费者醒来看的是
  "有货**或**关门"，不是只看"有货"

**零输出**照旧；注释不要求；main 留空；判题端多生产多消费压测。

## 需求

**Q1. 线程安全队列 `template <typename T> class TsQueue`（验收主菜）**
- `push(T)`：入队并唤醒一个等待者；**队列已关闭时抛 `std::runtime_error`**
- `pop() -> std::optional<T>`：**阻塞**直到"有元素或（已关闭且空）"——
  拿到元素返回它；队列空且已关闭返回**空 optional**。
  **必须用谓词形式的 wait**（防虚假唤醒/丢失唤醒——判题代码审查）
- `try_pop(T&) -> bool`：非阻塞版，空立即返回 false
- `close()`：置关闭标志并**唤醒所有**等待者
- `closed()` / `size()` 查询

**Q2.（SR 主考）三个坑的机理**：虚假唤醒为什么存在、丢失唤醒怎么发生、
为什么关停必须 notify_all 而不是 notify_one——SR 逐条讲清。

## 验收标准（判题端驱动核对；挂起由外部 timeout 判死刑）

- 多生产多消费：4 生产者各 push 1000 个数（每生产者的数字总和已知），
  2 消费者 pop 到 nullopt 为止累加——**总和精确等于全体生产者之和**，
  多次运行稳定
- 关停语义：生产者全部收工后 `close()`；消费者收完余货拿到 nullopt 退出
- `push` 在 close 后抛 runtime_error（驱动 catch 验证）
- `try_pop` 空队列立即 false，不阻塞
- pop 的 wait 必须是谓词形式（代码审查，非谓词版直接判 FAIL）
- 零输出零警告

## 约束

- 底层容器用 `std::deque`；允许 17 号同款 mutex/lock_guard/unique_lock
- **pop 必须谓词 wait**（裸 wait 判 FAIL）；notify 放锁内外皆可（说明理由更好）
- 零输出；C++17；接口名逐字符照抄（第七查）；改完自己编译
