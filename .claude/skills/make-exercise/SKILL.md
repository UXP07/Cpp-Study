# make-exercise — 需求式出题工作流

## 0. 前置事实

- **知识点清单**：`log/knowledge.md` —— 唯一序号 `#`、学习内容、验收标准、状态
- **练习进度**：`log/progress.md` —— 练习号全局递增（出题取号、判题通过后添行）
- **两套编号**：知识点号（学什么）≠ 练习号（exercises/NN）
- 每道题产出两个文件：
  - `exercises/NN_topic/REQUIREMENT.md` —— 需求文档，**用户唯一应看的文件**
  - `.claude/answers/NN_topic.md` —— 标准答案，**判题参照，用户不应提前查看**
- 用户自己写 `exercises/NN_topic/main.cpp`（可加其他文件）；新目录被 CMake 自动发现

## 1. 出题流程（"按 N 号出 M 道题"）

1. 校验 `log/knowledge.md`：号不存在 → 列候选请确认；已学习 → 提醒；前置波次大多未学 → 温和提醒。M 未指定默认 1 道
2. 命题设计（知识库为主，可经 smart-search 用 opencli 参考题型，不照抄）：
   - **需求式**：Q1、Q2、…纯文字需求描述——背景 + 要实现什么 + 行为要求
   - **不给任何代码骨架、不给函数签名**——用户从零设计，训练"想法 → 代码"的能力
   - 题目要有综合度：一道题至少覆盖该知识点的两三个侧面，避免单一语法默写
   - 验收标准写成**可观察行为**（程序输出、可验证属性），判题据此机器验证
   - 附 2–4 道简答题 SR1、SR2…（概念理解与辨析）
   - 视知识点附加约束（如"本题禁止使用 std::vector"）
3. 写 `REQUIREMENT.md`（模板见下）
4. 写标准答案 `.claude/answers/NN_topic.md`（模板见下），以专家视角完成：
   - 完整**可编译可运行**的参考实现
   - 评分要点 = 判题依据
5. 出题后将 knowledge.md 该行状态改为 `学习中`
6. 报告用户：题目位置、作答方式（自己建 main.cpp；简答题答案写在 main.cpp 顶部注释块；写完说"判题"）

## 2. REQUIREMENT.md 模板

```markdown
// 练习 NN —— 主题（知识点 #N 名称；复习题则标注"复习：对应练习 XX"）

## 背景
（一段真实感的场景描述）

## 需求
Q1. （行为要求，纯文字）
Q2. …

## 验收标准
- （程序可观察的行为，判题逐条核对）
- …

## 简答题（答案写在 main.cpp 顶部注释块）
SR1. …
SR2. …

## 约束
- （禁止事项 / 环境说明）
```

## 3. 标准答案模板（.claude/answers/NN_topic.md）

```markdown
# 练习 NN 标准答案 —— 主题

## 参考实现
（完整可编译的 C++ 代码，代码规范：终端输出英文、注释中文）

## 设计意图
（关键决策及理由：为什么这样设计）

## 评分要点
- 必须实现的行为（对应 Q1…）
- 边界与异常路径要求
- 质量要求（简洁/效率/可读性）

## 常见错误预测（判题重点检查）
- （预判用户可能犯的错，逐条）

## 模式点拨（判题时向用户点明）
- （本题涉及的可复用固定模式/架构：名称 + 适用场景 + 迁移提示）
```

## 4. 复习题（"出复习题"）

- 从 `log/progress.md` 已 PASS 的练习抽主题：优先用户曾出错的（点评列有记录）、久未复习的
- 出**变体需求题**（换场景、加一层深度），不重复原题
- REQUIREMENT.md 标注"复习：对应练习 NN / 知识点 #N"
- 标准答案的"常见错误预测"首条 = 该练习上次犯过的错，判题时核查是否重犯

## 5. 约定提醒

- 出题后**不判题不提示实现**（判题归 judge-exercise）；用户卡住求助时只给方向性提示
- `exercises/test/` 是用户草稿区，不涉及
- 中文交流；代码输出英文、注释中文
- 不自动 git commit
