# make-exercise — 知识点驱动的出题工作流

## 0. 前置事实

- **知识点清单**：`log/knowledge.md` —— 唯一序号 `#`、学习内容、验收标准、状态（未学习/学习中/已学习）
- **练习进度**：`log/progress.md` —— 练习号全局递增
- **两套编号**：知识点号（学什么）≠ 练习号（exercises/NN 做过什么）。出题时从 progress.md 取下一个练习号
- **公共工具**：`include/tester.h`（CHECK / CHECK_EQ / tester::summary()）

## 1. 出题（用户："按 N 号出 M 道题"）

1. 读 `log/knowledge.md` 校验：
   - N 不存在 → 列出编号范围与最接近候选，请用户确认
   - 状态为"已学习" → 提醒并确认是否继续
   - 所属波次的前置波次大多未学 → 温和提醒依赖关系，但尊重用户选择
   - M 未指定 → 默认 1 道
2. 命题来源（默认知识库；可结合两者）：
   - **opencli 互联网参考**：经 smart-search 检索"<知识点英文> exercise / interview questions"等，参考题型角度与难度；**不得照抄原题**，须改编为本工作区上下文
   - **知识库直接命题**
3. 每道题落地（共 M 个）：
   - 取下一个练习号 NN → 目录 `exercises/NN_topic/`（topic 英文小写下划线）
   - `main.cpp` 顶部注释块：知识点 `#N 名称`、题目背景、任务 TODO 清单、提示；（概念题）附口头追问
   - 骨架：函数签名 + TODO 标记，**不给实现**
   - 断言：CHECK/CHECK_EQ 覆盖该知识点验收标准（验收标准的机器化落地）；骨架态必须可编译，断言允许 FAIL
   - 平台适配：知识点带 `[Linux]/[GPU]/[Python]` 标注且本机不满足时，改为可编译的概念/设计/代码阅读题，或说明该题需指定环境运行
4. 出题后将 knowledge.md 该行状态改为 `学习中`
5. 验证骨架可编译：`cmake --build --preset default --target NN_topic`
6. 向用户报告：题目位置、构建与运行命令

## 2. 验收（用户："我做完了 / 验收"）

1. 编译对应练习，要求**零警告**
2. 运行 exe：全部 `[PASS]` 才算通过；失败时报告失败的断言与输出，不主动给修法（用户问了再给）
3. code review：bug、未定义行为、风格、更优写法；**除非用户要求，不直接改用户代码**
4. 通过后更新 `log/progress.md` 添行：练习号、主题、知识点 #N、日期、一句话点评
5. 提示用户：是否将知识点标为"已学习"由用户决定（建议同一知识点 ≥2 道题全过再标）

## 3. 标记已学习（用户："把 N 号标为已学习"）

1. 校验 N 存在；若其练习尚未全部通过，提醒（仍尊重用户决定）
2. `log/knowledge.md` 该行状态改为 `已学习（YYYY-MM-DD）`
3. 简报：当前波次完成度、按顺序建议的下一个知识点
4. **不自动 git commit**（提交时机由用户决定）

## 4. 查询（用户："进度 / 知识点列表"）

- 汇总 knowledge.md 各波次状态统计 + progress.md 最近完成的练习，给出下一步建议

## 约定提醒

- 新练习目录会被 CMakeLists.txt 自动发现，无需改构建配置
- 一律使用中文与用户交流；代码与标识符用英文
- CLAUDE.md 中的目录职责规则优先（doc/ 不写文件等）
