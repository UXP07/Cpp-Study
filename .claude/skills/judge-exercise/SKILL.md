# judge-exercise — 判题工作流

**用户的成长目标**：自如运用 C++，针对项目写出简洁高效、科学合理的代码。判题按此标准从严，毫不留情。

## 1. 定位练习

- 用户指定练习号 → 用之；未指定 → 取最近出题或最近修改的练习
- 读取三件套：`exercises/NN_topic/REQUIREMENT.md`、`.claude/answers/NN_topic.md`（判题参照）、用户代码（`exercises/NN_topic/` 下全部 .cpp/.h）
- 缺需求文档的旧练习（骨架式）→ 按旧规则验收（断言全 PASS + review）

## 2. 机器验证（先跑再评，度量不猜测）

1. **编译**：`cmake --build --preset default --target NN_topic` —— 零警告；有警告即列为问题
2. **运行**：`./build/bin/NN_topic.exe`，对照 REQUIREMENT.md 验收标准逐条核对
3. **功能深挖**：必要时代写小脚本/驱动程序验证——边界输入、异常路径、多线程压测、输出正确性比对（可编译标准答案对比输出）。临时脚本放 `build/tmp/`，判完删除，不污染源码
4. **简答题**：逐条评改（对照标准答案要点），错的概念当场讲清

## 3. 评审（毫不留情原则）

- 语气直接，不客套，问题就是问题；但**每条必须给"为什么要这样改"的原理和修改方向**
- 每处问题标注 `文件名:行号`，方便定位
- 四级分类：
  - `[错误]` bug / 未定义行为 / 与需求不符 —— **必须改**
  - `[缺失]` 需求未实现 / 边界遗漏 —— **必须改**
  - `[质量]` 简洁性 / 效率 / 可读性 —— 强烈建议
  - `[模式]` 固定模式与架构点拨 —— 用户明确要求：显式**命名**可复用模式（如"三步赋值""初始化列表优先""copy-and-swap""RAII 守卫"），讲清适用场景与迁移方式；用户接受死记硬背，鼓励背下来灵活套用
- 对照标准答案的"常见错误预测"逐条核查是否命中；复习题必查上次错误是否重犯
- 修正代码**由用户自己写**：只指错误+原理+方向，除非用户明确要求给出代码

## 4. 循环整改

- 输出**编号修改清单**（[错误]/[缺失] 必改项 + [质量]/[模式] 建议项）
- 要求用户逐项修复后再次说"判题"，重新执行第 2–3 步
- 循环直到：无 [错误] 无 [缺失]、简答题全部合格

## 5. 通过后

1. **写总结**：本题学到什么、暴露的思维/模式盲区、与以往练习的关联、值得记住的模式清单
2. 更新 `log/progress.md` 添行：练习号、主题、知识点 #N、日期、结果、一句话点评（点评要记录曾犯的错误，供复习题选题）
3. 提示用户：是否将 knowledge.md 对应知识点标"已学习"（用户决定，建议知识点级 ≥2 题全过）
4. 不自动 git commit

## 6. 约定

- 中文交流；用户代码里输出应为英文、注释应为中文（违反列为 [质量] 问题）
- 判题顺序固定：机器验证 → 评审 → 清单；不因用户催促跳过验证
- 判题中发现的系统性问题（反复出现的毛病）在总结中显式点名
